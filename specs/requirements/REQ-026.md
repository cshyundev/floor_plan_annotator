# REQ-026: Project Lifecycle Management

- **Status**: Proposed
- **Description**: The system shall provide explicit project lifecycle controls including new project creation, save/save-as distinction, unsaved-change tracking, and title bar feedback to prevent data loss.

## New Project (File > New, Ctrl+N)

- Clears all annotations and background from the canvas
- If unsaved changes exist, shows a confirmation dialog ("Save changes before creating a new project?") with options: Save / Don't Save / Cancel
- Resets the current file path so the next Save triggers Save As

## Save (File > Save, Ctrl+S)

- If a file path is already set, overwrites the file immediately without a dialog
- If no file path is set (new project), falls back to Save As behavior

## Save As (File > Save As, Ctrl+Shift+S)

- Always opens a file selection dialog (JSON Files (*.json))
- Updates the current file path to the chosen location
- Updates the title bar accordingly

## Unsaved Change Tracking (Dirty State)

- The `QUndoStack.cleanChanged` signal drives the dirty flag
- A dirty project shows `[*]` or `*` suffix in the title bar
- Saving marks the undo stack as clean

## Title Bar

Format: `Floor Plan Annotator — <filename>.json *`

- `<filename>` is the base name of the current file (no path)
- `*` appended when dirty; absent when clean
- When no file is open (fresh start): `Floor Plan Annotator`

## Application Close

- On close event, if dirty, shows the same Save / Don't Save / Cancel dialog
- Cancel aborts the close

## Implementation Notes

- `_current_file_path: Optional[str]` field in `MainWindow`
- Connect `undo_stack.cleanChanged` to a `_on_dirty_changed(dirty: bool)` slot
- `_do_save(path: str)` — common save logic called by both Save and Save As
- `_confirm_discard_changes() -> bool` — prompts the dialog, returns True if safe to proceed
