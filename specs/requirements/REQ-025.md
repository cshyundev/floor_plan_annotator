# REQ-025: Object 3D Properties (Elevation & Height)

- **Status**: Proposed
- **Description**: Each object annotation shall have per-instance 3D properties (elevation and 3D height) that define its vertical position and extent in 3D space. Object types provide default values; individual instances can override via the Properties Panel or mouse wheel interaction.

## Per-Type Defaults
- Each object type in `config/objects.yaml` defines `default_elevation` (z offset from floor, default 0.0m) and `default_3d_height` (vertical extent, default 0.5m)
- New objects inherit defaults from their type automatically
- The global `annotation_3d.object_height` config key is retained as the fallback for types without explicit defaults

## Per-Instance Editing

### Properties Panel
- "3D Properties" section with "Elevation" and "3D Height" spinboxes in the Object page
- Editing creates an undo-able `ChangeObject3DPropertiesCommand`

### Mouse Wheel Interaction
- `Ctrl + Wheel`: Adjust 3D Height (step 0.1m)
- `Ctrl + Shift + Wheel`: Adjust Elevation (step 0.1m)
- Status bar shows current value during adjustment
- Only active when a single ObjectItem is selected

## Type Change Behavior
- When object type changes, elevation and 3D height reset to the new type's defaults
- Previous values are captured for undo

## 3D Viewer
- `sync_object_annotation()` uses per-object elevation and height_3d instead of global `annotation_3d.object_height`
- z_min = floor_level + elevation, z_max = z_min + height_3d
- `ObjectGeometryBuilder.create_object_box()` already accepts z_min/z_max (no signature change)

## Data Model
- `Object` already inherits `z_min`/`z_max` from `AnnotationBase`
- `DataSerializer` serializes: `z_min = elevation`, `z_max = elevation + height_3d`
- ObjectItem stores `elevation` and `height_3d` properties

## Backward Compatibility
- Old project files with `z_min=0.0, z_max=2.5` (AnnotationBase defaults) are treated as "not explicitly set" and use type defaults instead
