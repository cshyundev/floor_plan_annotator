# REQ-019: Annotation Interaction Rules

- **Status**: Implemented
- **Description**: Defines interaction priority and behavior rules when annotations overlap on the 2D canvas.

## Display Hierarchy (bottom to top)

| Order | Type | Description |
|---|---|---|
| 1 (bottom) | Background image | Slice image from 3D point cloud |
| 2 | Room | Room boundary polygon |
| 3 | Custom Polygon | User-defined region |
| 4 | Object | Furniture/appliance bounding box |
| 5 | Wall | Wall line segment |
| 6 (top) | Node | Polygon/wall vertex |

## Interaction Scope by Tool

### Select Tool
- All annotation types are interactable.
- Repeated clicks at the same position cycle through overlapping annotations (top → bottom → wrap to top).
- Nodes are excluded from cycling and always take priority.
- The status bar shows the current cycle position.
- Rubber-band (drag) selection includes only annotation bodies; child elements (labels, handles) are automatically excluded.

### Drawing Tools (Wall / Room / Custom Polygon / Object)
- Only annotations of the **same type** as the active tool are interactable (select, drag, rotate).
  - Example: Room tool → existing rooms can be manipulated; existing objects and custom polygons are ignored.
  - Example: Object tool → existing objects can be manipulated; existing rooms and custom polygons are ignored.
- Annotations of **different types** do not respond to mouse events at all.
- When drawing is already in progress (nodes have been placed, or a drag is ongoing), drawing takes priority over same-type annotation interaction.

## Priority Summary

1. **Drawing in progress** → New annotation drawing takes highest priority
2. **Drawing idle + click on same type** → Existing annotation manipulation
3. **Drawing idle + click on different type** → Ignored (treated as click on empty space)
4. **Select tool** → All types interactable with cycle selection support
