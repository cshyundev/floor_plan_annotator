# REQ-029: Auto-save Recovery

- **Status**: Proposed
- **Description**: The system shall periodically auto-save the current project to a temporary file so that work can be recovered after an unexpected crash or power loss.

## Auto-save Trigger

- Auto-save fires every 5 minutes when both conditions are met:
  1. A file path is set (`_current_file_path` is not None)
  2. The project is dirty (has unsaved changes)
- Auto-save does **not** run for brand-new projects that have never been saved (no path yet)

## Auto-save File

- Location: same directory as the project file
- Name: `.<filename>.autosave.json` (hidden file, dot-prefixed)
- Example: project at `/maps/lobby.json` → auto-save at `/maps/.lobby.autosave.json`

## Recovery on Startup

- On launch, `MainWindow` checks whether any auto-save files exist adjacent to entries in the recent files list
- If found, a non-blocking dialog appears:
  > "An auto-saved version of 'lobby.json' was found from [timestamp].
  > Do you want to recover it?"
  > [Recover] [Discard]
- **Recover**: opens the auto-save file and sets the current path to the original path (so the next Save overwrites the original)
- **Discard**: deletes the auto-save file silently

## Cleanup

- The auto-save file is deleted when:
  - The user performs a successful manual save (Save or Save As)
  - The user clicks "Discard" in the recovery dialog

## Implementation Notes

- `QTimer` with 5-minute interval in `MainWindow`
- Auto-save reuses `ProjectIO.save_project()` with the auto-save path
- Auto-save failures are silently ignored (no dialog) to avoid interrupting the user
- The timer is restarted after each auto-save or manual save
