# REQ-030: Project Folder Structure Convention

- **Status**: Accepted
- **Description**: The system shall define a clear convention for how a project is organized on disk. One project folder corresponds to exactly one map dataset and one annotation file named `annotations.json`.

## Decision

**1 folder = 1 map dataset + `annotations.json`.**

The annotation file is always named `annotations.json` and resides in the same directory as the map data file. The `image_path` field inside `annotations.json` records the relative path to the map data, establishing the pairing.

## Supported Data Source Types

The "map dataset" can be any of the following:

| Category | File Types | Description |
|----------|-----------|-------------|
| Occupancy Grid | `.pgm`, `.png` + `.yaml` | ROS2 map_server format |
| Point Cloud | `.ply`, `.pcd` | XYZ + optional RGB |
| Mesh (no texture) | `.ply`, `.obj`, `.stl` | Triangle mesh with optional vertex colors |
| Mesh (with texture) | `.glb`, `.gltf` + optional `.bin`/`.png` | Textured 3D model (see REQ-031) |

## Recommended Folder Layouts

### Occupancy Grid
```
my_project/
├── map.pgm          (or map.png)
├── map.yaml         (optional ROS2 metadata)
└── annotations.json
```

### Point Cloud / Simple Mesh
```
my_project/
├── scan.ply         (or scan.pcd, model.obj, …)
└── annotations.json
```

### GLB (self-contained)
```
my_project/
├── model.glb        (all textures embedded)
└── annotations.json
```

### GLTF + external assets
```
my_project/
├── model.gltf
├── model.bin        (binary buffer)
├── texture_0.png    (texture image)
└── annotations.json
```

## Entry Points

The app supports two entry points — both are equivalent:

### Entry Point A: Open 3D data file first
- User opens the 3D data file via **File > Load 3D Data...** or **File > Load Occupancy Grid...**
- App looks for `annotations.json` in the same folder
- If found, validates that `annotations.json.map_metadata.image_path` basename matches the loaded file
- On match: loads annotations silently
- On mismatch: warns the user and does NOT auto-load

### Entry Point B: Open annotations.json directly
- User opens `annotations.json` via **File > Open Annotations... (Ctrl+O)**
- App reads `map_metadata.image_path`, resolves the absolute path relative to the JSON file location, and auto-loads the 3D data

Both entry points result in the same state: 3D data loaded + annotations loaded + `_current_file_path` set to `annotations.json`.

## Save Behavior

- **Ctrl+S (Save)**: writes to `{3d_data_folder}/annotations.json` automatically (no dialog needed when 3D data is loaded)
- **Ctrl+Shift+S (Save As)**: opens a file dialog to choose a custom path

## Pairing Validation

When auto-detecting `annotations.json` on 3D load (Entry Point A), the app compares:

```
os.path.basename(annotations.json["map_metadata"]["image_path"])
    ==
os.path.basename(loaded_3d_file_path)
```

If they differ, the annotations are for a different dataset and must not be loaded automatically.

## Multi-Floor Buildings

Each floor is a separate project folder:

```
building_site/
├── floor_b1/
│   ├── map.pgm
│   └── annotations.json
├── floor_1f/
│   ├── map.pgm
│   └── annotations.json
└── floor_2f/
    ├── map.pgm
    └── annotations.json
```

The app opens one floor at a time. Cross-floor features are out of scope for now.

## Why This Convention

| Concern | How it is addressed |
|---------|-------------------|
| Portability | Relative `image_path` keeps the pair intact when the folder moves |
| Simplicity | Fixed filename `annotations.json`; no ambiguity about which file to load |
| Discoverability | Both opening directions (3D first or JSON first) work naturally |
| Tooling | File pickers, version control, and zip archives all work naturally |

## Trade-offs Accepted

- **Single annotation file per folder**: Multiple annotation layers for the same map require separate subfolders. Accepted for now given the single-robot-map use case.
- **No enforcement**: The app cannot force users to place files in the same folder, but warns when the map file cannot be found and falls back to a file picker dialog.

## Impact on Other REQs

- **REQ-026 (Lifecycle)**: Save derives path as `{3d_data_folder}/annotations.json` automatically.
- **REQ-028 (JSON Schema v4.0)**: `image_path` is always stored as a relative path. `image_path_absolute` is runtime-only.
- **REQ-027 (Recent Files)**: Recent files list stores absolute paths to `annotations.json` files (not folders).
