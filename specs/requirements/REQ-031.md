# REQ-031: GLB/GLTF Data Source with Texture Support

- **Status**: Accepted
- **Description**: The system shall support loading GLB/GLTF 3D models including embedded or externally referenced textures, and shall bake texture colors onto mesh vertices so the existing height-slicing and 2D color projection pipeline can process them without modification.

## Motivation

The current loader supports PLY/PCD point clouds and OBJ/STL meshes with vertex colors only.
GLB/GLTF models (common output of photogrammetry, BIM export, and robotics scanning tools) store color as UV-mapped texture images rather than per-vertex colors. The slicing pipeline (`processor.py`) operates on per-vertex/per-point colors, so texture data must be baked into vertex colors at load time.

## Supported Formats

| Format | Description |
|--------|-------------|
| `.glb` | Binary GLTF — single file, textures embedded as base64 |
| `.gltf` | Text GLTF — references external `.bin` and texture image files |

## Load Behavior

### Step 1 — File detection
The loader detects GLB/GLTF by file extension (`.glb`, `.gltf`) before attempting Open3D.

### Step 2 — Load with trimesh
`trimesh.load(path)` is used for GLTF loading.
- GLB: single file, no additional assets needed
- GLTF: `path` must point to the `.gltf` file; `.bin` and texture images are resolved from the same directory automatically by trimesh

### Step 3 — Scene flattening
If the loaded object is a `trimesh.Scene` (multiple meshes), all sub-meshes are merged into a single mesh via `trimesh.util.concatenate(scene.dump())`.

### Step 4 — Texture baking to vertex colors
```
mesh.visual.to_color()
```
This samples the UV-mapped texture image at each vertex's UV coordinate and writes the result as `mesh.visual.vertex_colors` (RGBA uint8). This is the key step that makes textured models compatible with the rest of the pipeline.

### Step 5 — Convert to Open3D TriangleMesh
The vertex positions, face indices, and baked vertex colors are transferred to an `o3d.geometry.TriangleMesh`. Vertex normals are computed automatically. This object is then treated identically to any other mesh by the existing pipeline.

## Pipeline Compatibility

After Step 5 the data is identical in type to a PLY mesh with vertex colors. No changes are required in:
- `processor.py` (`_load_mesh`, `_project_color`)
- `viewer_3d.py` (renders vertex colors via `defaultLit` shader)
- `annotation_sync.py`
- `data_serializer.py`

## File Picker

`QFileDialog` in `main_window.load_point_cloud()` shall include:
```
3D Data Files (*.ply *.pcd *.obj *.stl *.glb *.gltf)
```

## ProjectData / JSON Impact

`MapMetadata` currently stores `image_path` (path to `.pgm`/`.png`).
For GLB/GLTF the same field stores the path to the `.glb` or `.gltf` file.
No schema change is required; field semantics are generalized to "data source path".

As part of REQ-028 (v4.0 schema), the field should be renamed from `image_path` to `data_path` to reflect that it now covers non-image sources.
`image_path` is kept as a legacy alias when loading v1.0–v3.0 files.

## Dependency

Add `trimesh[easy]` (includes `pillow` for texture image decoding and `pygltflib` for GLTF parsing).

```toml

```

### `viewer_3d.py` — `load_geometry()` new branch

```python
def load_geometry(self, file_path: str):
    ext = Path(file_path).suffix.lower()
    if ext in (".glb", ".gltf"):
        geom = self._load_gltf(file_path)
    else:
        # existing Open3D path
        geom = o3d.io.read_point_cloud(file_path)
        if geom.is_empty():
            geom = o3d.io.read_triangle_mesh(file_path)
            geom.compute_vertex_normals()
            if not geom.has_vertex_colors():
                geom.paint_uniform_color([0.7, 0.7, 0.7])
    # ... rest unchanged (downsampling, scene update)
```

### `viewer_3d.py` — `_load_gltf()`

```python
def _load_gltf(self, path: str) -> o3d.geometry.TriangleMesh:
    import trimesh
    loaded = trimesh.load(path, force="mesh")
    if isinstance(loaded, trimesh.Scene):
        loaded = trimesh.util.concatenate(loaded.dump())
    # Bake UV texture → vertex colors
    if hasattr(loaded.visual, "to_color"):
        loaded.visual = loaded.visual.to_color()
    vertices = np.asarray(loaded.vertices, dtype=np.float64)
    faces = np.asarray(loaded.faces, dtype=np.int32)
    colors = np.asarray(loaded.visual.vertex_colors, dtype=np.uint8)[:, :3] / 255.0
    mesh = o3d.geometry.TriangleMesh()
    mesh.vertices = o3d.utility.Vector3dVector(vertices)
    mesh.triangles = o3d.utility.Vector3iVector(faces)
    mesh.vertex_colors = o3d.utility.Vector3dVector(colors)
    mesh.compute_vertex_normals()
    return mesh
```

### `main_window.py` — data source dispatch

```python
def _restore_data_source(self, metadata: MapMetadata, project_path: str):
    ext = Path(resolved_path).suffix.lower()
    if ext in (".yaml",):
        self._load_occupancy_grid_from_yaml(...)
    elif ext in (".glb", ".gltf", ".ply", ".pcd", ".obj", ".stl"):
        self.load_data(resolved_path)
    elif ext in (".pgm", ".png"):
        self._load_occupancy_grid_image_only(...)
```
